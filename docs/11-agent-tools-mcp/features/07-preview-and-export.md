# F07. 페이지를 확인하고 PDF로 전달하기

상태: 구현 기준안 · 우선순위: P1 · 사용자 여정: UJ-07

[기능 전체](../README.md) · [도구 계약](../tool-contracts.md)

## 1. 문제와 배경

문장의 저장 성공만으로 문서 작성이 끝나지 않는다. 문장이 길어져 다음 페이지로 넘어가거나, 이미지·글꼴이 빠지거나, 인쇄 결과에서 내용이 잘릴 수 있다. 사용자는 작성 결과를 확인하고 다른 사람에게 보낼 PDF를 얻어야 한다.

활성 편집 화면을 출력 작업에 사용하면 사용자가 입력하던 문서·선택·포커스를 건드릴 수 있다. 따라서 요청한 저장 revision을 별도 숨겨진 renderer에서 출력하고, 결과가 어느 저장본인지 알려준다.

## 2. 사용자와 역할

작성자는 결과를 검토하고 PDF를 열거나 저장한다. 에이전트는 preview 이미지와 경고를 확인해 추가 수정이 필요한지 판단하고 PDF 출력을 요청한다. Formleaf는 같은 저장본의 레이아웃을 재현하고 접근 권한이 있는 연결에만 출력물을 제공한다.

에이전트가 이미지의 미적 품질을 평가하는 능력은 클라이언트마다 다르다. Formleaf는 페이지 이미지·페이지 수·경고를 제공하며 '디자인 검수 완료'를 자동 보증하지 않는다.

## 3. 목표와 성공 기준

- 출력 revision이 명시되어 사용자가 현재 초안과 저장본을 혼동하지 않는다.
- 한글·목록·component·repeater가 포함된 fixture에서 저장·재열기·PDF의 본문 의미와 순서를 유지한다.
- 편집 중 출력해도 활성 editor root, caret, composition과 문서 선택을 유지한다.
- 에이전트가 host의 임의 경로를 쓰지 않아도 사용자는 앱에서 PDF를 열고 원하는 위치에 따로 저장할 수 있다.

## 4. 사용 시나리오 — UJ-07

사용자는 '경력 내용을 다듬은 결과를 확인하고 PDF로 만들어줘'라고 요청한다. 문서 읽기와 render가 허용되어 있다.

1. 에이전트가 수정 결과의 revision을 확보한다. 미저장 입력이 있으면 마지막 저장본을 출력한다는 사실을 설명한다.
2. 해당 revision의 첫 페이지 preview를 요청하고 페이지 수·경고를 확인한다. 필요한 다른 페이지도 개별 조회한다.
3. 내용이나 레이아웃을 수정했다면 새 저장 revision으로 preview를 다시 확인한다.
4. 에이전트가 PDF 출력 requestId를 만들고 job을 요청한다. pending 응답은 출력 완료가 아니다.
5. get_operation으로 완료 여부를 확인하고 artifact URI와 만료 시각을 얻는다.
6. 사용자가 Formleaf 작업 결과에서 PDF를 열거나 다른 위치에 저장한다. 지원하는 클라이언트는 MCP resource로 PDF를 읽을 수 있다.

종료 상태: 사용자는 어느 저장본으로 만든 PDF인지 알 수 있고 출력물에 접근할 수 있다. 출력 도중 다른 편집을 해도 이미 수락한 snapshot은 바뀌지 않는다.

## 5. 상세 요구와 예외

- **F07-R01 — 저장본 고정:** 수락 시 expectedRevision을 검사하고 snapshot을 고정한다. 이후 편집은 출력 job에 섞지 않는다. 미저장 draft를 몰래 저장하거나 출력하지 않는다.
- **F07-R02 — 준비 완료 확인:** fonts/images/pagination 준비 후 캡처한다. 준비 실패·시간 초과를 성공으로 표시하지 않는다. 외부 URL을 새로 다운로드하지 않고 미해결 리소스는 경고한다.
- **F07-R03 — 편집 독립:** 사용자 창 전환·문서 열기·선택 변경·강제 blur 없이 출력한다. 활성 편집 보호는 출력 중 부모 rerender에도 유지되어야 한다.
- **F07-R04 — 제한된 출력:** 페이지 preview는 한 페이지씩, PDF는 비동기 job이다. 크기·시간 한도는 도구 계약을 따른다. 요청 페이지가 없으면 PAGE_OUT_OF_RANGE를 반환한다.
- **F07-R05 — 접근과 보관:** artifact는 발급 연결과 현재 문서/render 권한을 함께 검사한다. 24시간 후 만료하며 새 출력은 새 requestId가 필요하다. 같은 요청 재전송으로 만료 파일을 다시 생성하지 않는다.
- **F07-R06 — 사용자 파일 보호:** filename은 안전한 basename이다. 사용자가 고르는 저장 위치는 앱의 저장 UX에서 처리한다. 자동 정리는 MCP artifact 디렉터리의 만료분만 대상으로 하며 사용자 PDF·문서·backup에 접근하지 않는다.

출력 실패 시 에이전트는 경고·오류를 사용자에게 전달하고 저장된 문서는 유지한다. artifact 저장 예산이 가득 찼다면 아직 유효한 결과를 임의 삭제하지 않고 새 출력을 거절한다. 요청 결과가 불명확하면 F08의 조회 절차를 따른다.

## 6. 대안과 트레이드오프

| 대안 | 이점 | 비용·한계 | 판단 |
|---|---|---|---|
| 활성 화면 그대로 캡처 | 현재 초안을 즉시 보여준다 | 편집 상태·포커스와 출력 준비가 결합된다 | 미선택 |
| 저장 snapshot의 hidden renderer | 요청 revision을 재현하고 편집과 분리한다 | 별도 renderer 비용, 초안은 포함하지 못함 | 선택, D06 |
| 에이전트가 지정한 경로로 PDF 저장 | 다른 shell 작업에서 바로 사용 가능 | 파일 쓰기 범위와 덮어쓰기 통제가 추가로 필요 | 미선택 |
| 만료되는 artifact + 앱 저장 UX | 결과 접근과 정리 범위가 명확하다 | 사용자가 장기 보관하려면 별도 저장 필요 | 선택 |

## 7. 범위와 의존성

F01의 render 권한, F02의 저장 상태 조회, F08의 비동기 결과 조회가 필요하다. 실시간 draft preview·원격 파일 업로드·새 font 설치·문서 자동 디자인 평가는 포함하지 않는다.

## 9. 기술 연결과 남은 확인

T10 preview_document, T11 export_pdf, T12 get_operation과 artifact resource. 계획 5단계에서 구현하고 6단계에서 두 외부 클라이언트와 hidden Electron으로 검증한다.

클라이언트의 image/resource 표시 차이, 실제 글꼴과 PDF 내용 추출 결과는 구현 시 확인한다. 화면과 PDF의 픽셀 완전 일치를 성공 조건으로 삼지 않고 본문 의미·순서와 레이아웃의 잘림 여부를 각각 확인한다.

기술 실행 흐름: [실행 시퀀스](../runtime-flows.md)의 AS02→TB04의 출력 경로 전환를 함께 읽는다. 기능 간 의존성은 [설계](../design.md)의 기능 관계 절을 따른다.

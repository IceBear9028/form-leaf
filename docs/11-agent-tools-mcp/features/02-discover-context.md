# F02. 작업할 문서와 편집 대상 찾기

상태: 구현 기준안 · 우선순위: P0 · 사용자 여정: UJ-02

[기능 전체](../README.md) · [도구 계약](../tool-contracts.md)

## 1. 문제와 배경

'경력 설명을 고쳐줘'라는 요청에는 문서 이름, 반복 항목, prop ID가 모두 들어 있지 않다. 화면의 문단을 DOM 위치로 지정하면 pagination으로 위치가 달라지거나 컴포넌트 기본값과 instance 값을 혼동할 수 있다. 에이전트가 저장 파일 구조를 직접 추측하도록 하면 같은 이름의 항목을 잘못 수정할 가능성도 생긴다.

Formleaf는 문서의 개요와 수정 가능한 대상을 단계적으로 제공한다. 에이전트가 사람에게 보이는 이름·계층과 안정적인 ID를 연결한 뒤 필요한 값을 읽도록 한다. 사용자가 문서를 선택했다는 사실과 문서 내용을 변경하도록 요청했다는 사실은 구분한다.

## 2. 사용자와 역할

- 문서 작성자는 문서명·섹션명·현재 선택을 기준으로 요청한다. 내부 ID를 외울 필요가 없다.
- 에이전트는 후보를 찾고 대상이 명확하면 ID를 고정한다. 동명이인·동일 제목 등으로 결정할 수 없으면 사용자에게 구분을 요청한다.
- Formleaf는 현재 문맥과 마지막 저장 snapshot을 제공한다. 문장 의미를 해석해 수정 대상을 임의로 정하지 않는다.

## 3. 목표와 성공 기준

에이전트가 원본 저장 파일이나 DOM을 직접 읽지 않고 node·component prop·repeater item prop을 구분할 수 있어야 한다. 한 번에 모든 문서 본문을 전달하지 않고도 목표 값을 찾을 수 있어야 한다. 실제 검증에서는 이름이 같은 항목 두 개를 준비해 요청하지 않은 대상이 변경되지 않는지 확인한다. 화면에 보이는 미저장 draft와 읽은 저장값이 다를 때 그 차이를 숨기지 않는다.

## 4. 사용 시나리오 — UJ-02

사용자는 이력서의 두 번째 경력 항목을 선택한 뒤 외부 에이전트에 '이 항목의 담당 업무를 요약해줘'라고 요청한다.

1. 에이전트가 현재 문맥을 조회해 허용된 활성 documentId와 선택 target을 확인한다.
2. 선택 target이 없거나 요청한 내용과 맞지 않으면 이름으로 문서를 찾고 outline을 읽는다.
3. 편집 대상 목록의 label과 breadcrumb에서 '경력 → 두 번째 회사 → 담당 업무'를 찾는다.
4. 해당 target의 값과 revision, 기본값 상속 여부, Markdown 호환성을 읽는다.
5. 미저장 변경이 있으면 '현재 저장된 설명'이라는 사실을 밝히고 최신 저장을 기다린다. 저장값만으로 가능한 조회·요약은 계속할 수 있다.
6. 수정 작업에는 여기서 확인한 ID를 명시한다. 이후 사용자가 다른 요소를 클릭해도 자동으로 대상을 바꾸지 않는다.

종료 상태: 에이전트는 어떤 문서의 어떤 값에 대해 작업하는지 설명할 수 있고, 다음 수정 요청의 target과 revision이 확보된다.

## 5. 상세 요구와 예외

- **F02-R01 — 문맥과 대상 구분:** selection은 편의 정보다. 쓰기의 필수 documentId/target을 생략하게 하지 않는다. Markdown 내부 block을 별도의 문서 선택 단위로 노출하지 않는다.
- **F02-R02 — 단계적 조회:** 문서 이름 검색 → outline → target 목록 → 값 조회를 지원한다. canonical 조회는 구조·스타일·instance 값을 더 자세히 볼 때 사용한다.
- **F02-R03 — 의미 있는 대상 설명:** label, breadcrumb, 값 유형, default/override 여부를 함께 제공한다. archived prop은 직접 수정 대상으로 나열하지 않는다. 숨긴 요소는 숨김 상태를 설명한다.
- **F02-R04 — 저장 상태 표시:** 조회는 저장 snapshot 기준이며 dirty/editing 정보를 포함한다. IME 조합값을 완성된 값처럼 반환하지 않는다.
- **F02-R05 — 불완전 응답 방지:** pagination cursor가 가리키는 revision이 바뀌면 재조회를 요구한다. 응답 상한을 넘으면 본문을 몰래 자르지 않는다.

target이 숫자·boolean·image prop이면 text target 목록에서 찾는 대신 component 정의와 instance 값을 읽도록 안내한다. 사용자 질문이 모호한 경우의 대화는 외부 에이전트가 담당하며 Formleaf가 자동 확인 대화창을 띄우지는 않는다.

## 6. 대안과 트레이드오프

| 대안 | 이점 | 비용·한계 | 판단 |
|---|---|---|---|
| 항상 전체 canonical 문서 전달 | 호출 수가 적다 | 긴 문서·asset로 문맥이 커지고 필요한 target이 묻힌다 | 선택적 상세 조회만 제공 |
| DOM selector·페이지 위치로 대상 지정 | 화면과 바로 대응한다 | pagination·재렌더·컴포넌트 반복으로 identity가 흔들린다 | 미선택 |
| outline과 typed target의 단계적 조회 | stable ID와 의미를 함께 전달한다 | 여러 호출과 명확한 도구 설명이 필요하다 | 선택, D05 |

문서 전체 본문 검색은 제공하지 않아 많은 문서에서 내용을 탐색하는 데 한계가 있다. 첫 버전은 이름·현재 문맥·문서 내 target으로 작업을 시작하는 시나리오에 집중한다.

## 7. 범위와 의존성

F01의 읽기 grant가 필요하다. 조회는 쓰기 권한 없이 가능하다. 강제 문서 열기·caret 이동·미저장 draft 편집은 포함하지 않는다. F03–F07의 대상·revision 획득 단계가 된다.

## 8. 인수 조건

| ID | Given | When | Then |
|---|---|---|---|
| F02-AC01 | 같은 제목의 반복 항목 두 개 | target 목록과 값을 조회 | itemId·계층으로 두 항목을 구분 가능 |
| F02-AC02 | 문서가 미저장/조합 중 | 본문 조회 | 마지막 저장값과 dirty/editing 표시, 조합 상태 불변 |
| F02-AC03 | target A를 확보한 뒤 UI는 B 선택 | A를 명시한 후속 요청 | 대상이 B로 바뀌지 않음; revision/busy 검사는 별도 적용 |
| F02-AC04 | 목록을 읽는 중 revision 변경 | 이전 cursor 사용 | INVALID_CURSOR, 처음부터 조회 안내 |
| F02-AC05 | table/reference가 있는 Markdown | 값 조회 | 원문 그대로 반환하고 codec 호환성 별도 표시 |

## 9. 기술 연결과 남은 확인

T01–T05, 필요시 T09의 문서 component 조회. 도구 계약의 DocumentEditTarget과 조회 DTO를 사용한다. 계획 3단계에서 구현한다.

label/breadcrumb의 이해 가능성은 실제 문서 fixture를 사용하는 두 에이전트 검증에서 확인한다. '두 번째 회사'를 에이전트가 항상 올바르게 추론한다는 보장은 하지 않는다. 서버가 강제할 부분은 ID·유형 검증이고, 모호한 자연어 처리 품질은 별도로 기록한다.

기술 실행 흐름: [실행 시퀀스](../runtime-flows.md)의 TB01의 저장 문맥·target 조회를 함께 읽는다. 기능 간 의존성은 [설계](../design.md)의 기능 관계 절을 따른다.

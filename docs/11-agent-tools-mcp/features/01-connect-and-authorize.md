# F01. 에이전트 연결과 문서 접근 허용

**사용자 목표·동작·예외·인수 조건을 정의하는 기능 기획이다.**

- 상태: 기존 구현 완료 기록 기준 · 우선순위: P0 · 여정: UJ-01.
- [전체 기획](README.md) · [구현 설계 요약](../implementation/README.md).

## 1. 문제와 배경

**사용자가 에이전트에게 문서 하나의 수정을 맡겼다고 해서 개인 문서 전체의 조회까지 허용했다고 볼 수는 없다.**

- 단순히 로컬 서버 주소만 제공하면 어떤 문서와 동작이 열려 있는지 사용자가 확인하기 어렵다.
- 반대로 요청할 때마다 같은 허가를 묻는 방식은 반복적인 문서 작업을 방해한다.

**사용자는 Formleaf에서 연결별로 문서와 작업 범위를 정하고, 외부 에이전트는 그 범위 안에서 작업한다.**

- 여기서 연결하는 것은 문서 도구이며 모델 계정이 아니다.
- 사용자의 외부 에이전트는 이미 자신의 방식으로 로그인되어 있다는 전제를 둔다.

## 2. 사용자와 역할

| 행위자 | 책임과 기대 |
|---|---|
| 문서 소유자 | 연결을 만들고 읽기 허용 문서와 쓰기·생성·출력 권한을 정한다 |
| 외부 에이전트 | 발급된 credential로 접속하고 허용한 도구 기능을 사용한다 |
| Formleaf | 모든 요청과 결과 조회에서 최신 권한을 검사하고 폐기를 반영한다 |

**첫 대상은 본인 PC의 문서를 관리하고 외부 에이전트 설정을 사용할 수 있는 개인이다.**

- 조직의 사용자 초대·역할 관리와 원격 접속은 비범위다.

## 3. 목표와 성공 기준

- 사용자가 다른 문서를 공개하지 않고 특정 문서의 읽기 또는 수정만 맡길 수 있다.
- 연결 설정에서 현재 권한과 활성 여부를 확인하고, 에이전트에게 요청하지 않고도 폐기할 수 있다.
- 검증 fixture에서 비허용 문서의 본문·이름·목록·오류 상세·출력물이 모두 노출되지 않아야 한다.
- 연결 성공 횟수만 높이기 위해 인증을 생략하거나 전체 문서를 자동 허용하지 않는다.

## 4. 사용 시나리오 — UJ-01

**사용자는 이력서 A의 문장 수정을 맡기려고 한다.**

- 같은 workspace의 계약서 B는 공개하고 싶지 않다.
- Formleaf는 실행 중이며 MCP는 꺼져 있다.

1. 사용자가 에이전트 연결 화면에서 서버를 켠다. 서버 실행 여부와 실패를 표시하며 주소는 상세 안내에서 복사한다.
2. '에이전트 연결'에서 Codex·Claude Code·기타 클라이언트를 고르고, '이력서 도우미'라는 이름과 A를 선택한다. 기본 문서 집합은 비어 있고 쓰기 권한은 꺼져 있다.
3. 쓰기·출력을 허용하고 유효기간 7/30/90일(기본 30일)을 선택한다. 새 문서 생성·개인 라이브러리 전체 읽기는 별도 선택이다. 선택 범위를 token과 함께 원자적으로 저장한다.
4. 발급 직후 token을 복사하고 클라이언트별 환경 변수·설정·첫 요청 안내를 따른다. '연결 확인'에서 현재 토큰으로 인증된 MCP 요청이 실제 들어왔는지 확인한다. CLI 실행 여부나 AI 로그인 성공으로 표시하지 않는다.
5. 에이전트가 문맥을 조회하면 A만 사용할 수 있다. B를 열어 둔 경우에는 현재 문서 정보가 비어 있다고 응답한다.
6. 작업이 끝난 뒤 사용자가 연결을 폐기한다. 기존 세션의 다음 요청도 거절된다.

- 종료 상태: 사용자는 어느 연결에 무엇을 허용했는지 알고 있으며, 요청별 팝업 없이 허용 범위의 작업을 수행했다.

## 5. 상세 요구와 예외

**F01-R01 — 기본 비공개**

- MCP는 기본 비활성이고 새 연결의 문서 집합은 비어 있다.
- 사용자가 고른 문서와 capability만 저장한다.

**F01-R02 — 사람이 권한 관리**

- token 발급·권한 확대·폐기는 앱 UI에서만 제공한다.
- 도구 인자로 권한을 덮어쓸 수 없다. create는 write를 함께 요구한다.

**F01-R03 — 전체 응답 경로 검사**

- tools뿐 아니라 초기 문맥, resources, artifact, 작업 조회에도 적용한다.
- 문서 ID를 추측해 요청해도 존재 여부를 구분해 알려주지 않는다.

**F01-R04 — 실행 시 재확인**

- 접속 때만 검사하지 않는다.
- 대기 중인 작업은 실행 전에도 현재 grant를 확인한다.
- 이미 저장된 결과를 권한 폐기로 되돌리지는 않는다.
- 완료 결과의 재조회는 최신 권한을 따른다.

**F01-R05 — 복구 가능한 설정 오류**

- 포트 충돌은 서버 시작 실패로 표시하고 endpoint가 사용 가능하다고 표시하지 않는다.
- 앱 종료 시 연결은 종료된다. token 분실·만료 시 같은 연결에서 token을 교체하고 CLI 설정을 갱신한다.
- 원문 재조회는 제공하지 않는다.

**F01-R06 — 연결 관리 화면**

- 왼쪽 연결 목록, 오른쪽 문서와 권한/연결·보안/작업 기록 탭을 사용한다.
- 기존 Card·Dialog·Field·Input·Switch·Badge·AlertDialog와 앱 theme token을 재사용하며 프로토타입의 별도 브랜드 색·서체·가짜 메뉴는 이식하지 않는다.

**F01-R07 — token 수명**

- 새 UI 연결은 유효기간을 가진다.
- 교체 시 credential ID·grant·journal 소유권을 유지하면서 hash와 만료일을 갱신하고 구 token의 다음 요청을 거절한다.
- 기존 무기한 token은 자동 만료시키지 않는다.
- 폐기된 연결을 교체로 되살릴 수 없다.

**F01-R08 — 상태의 근거**

- 서버 실행, token 만료/폐기, 현재 앱 실행에서 현재 token으로 관측한 인증 요청을 구분한다.
- 요청 시각은 메모리에만 보관하고 앱 재시작·token 교체 뒤 다시 확인한다.
- 클라이언트 종류는 안내용 사용자 선택이며 호출자의 신원을 증명하지 않는다.

**F01-R09 — 편집/실패 보존**

- 2초 polling·탭 이동으로 권한 초안을 초기화하지 않는다.
- 원격 grant 변경을 감지하면 초안을 보존하고 최신 권한 재조회 전 저장을 막는다.
- 연결/화면 이동 시 미저장 변경 폐기를 확인한다.
- 발급 창을 닫거나 token을 숨기면 원문을 재표시하지 않는다.
- 교체·폐기는 영향 설명 후 확인하며 실패 시 dialog에서 재시도한다.


**읽기 전용 연결의 수정 요청은 거절한다.**

- 사용자는 앱에서 쓰기를 허용하거나 읽기 작업만 계속할 수 있다.
- 이 기능은 외부 shell이 가진 OS 권한까지 통제하지 않는다.

## 6. 대안과 트레이드오프

| 대안 | 이점 | 비용·한계 | 판단 |
|---|---|---|---|
| workspace 전체를 하나의 token으로 허용 | 설정이 짧다 | 새 문서까지 의도치 않게 공개될 수 있고 연결별 폐기가 어렵다 | 미선택 |
| 연결별 문서 목록과 capability | 사용자 의도와 허용 범위를 맞추고 독립 폐기 가능 | 문서가 늘면 권한 관리가 필요하다 | 선택, D02 |
| 매 쓰기마다 승인 | 변경 시점에 사람이 검토할 수 있다 | 여러 명령의 반복 승인으로 자동 작업이 끊긴다 | v1 미포함 |

**로컬 앱 서버는 설치·문서 상태를 공유하기 쉽지만 Formleaf가 켜져 있어야 한다(D01).**

- 외부 에이전트 자체를 sandbox 안에서 실행하는 기능은 후속 작업이다.

## 7. 범위와 의존성

**연결 설정·인증·문서 grant·폐기·상태 표시를 포함한다.**

- AI 로그인·채팅·에이전트 설치는 제외한다.
- F02–F08의 모든 조회와 변경은 이 권한 경계에 의존한다.

## 8. 인수 조건

| ID | Given — 전제 | When — 행동 | Then — 관찰할 결과 |
|---|---|---|---|
| F01-AC01 | A만 허용, B는 비허용 | B 목록·본문·현재 문맥·resource 요청 | B 이름·내용 없이 null/필터링/동일 접근 오류 |
| F01-AC02 | A 읽기만 허용 | A 수정 요청 | CAPABILITY_DENIED, 저장값 불변 |
| F01-AC03 | 연결된 세션 존재 | 사용자가 token 폐기 후 재요청 | 기존 session ID가 있어도 인증 거절 |
| F01-AC04 | 출력 대기 중 권한이 철회됨 | job 실행 또는 artifact 읽기 | 최신 grant에 따라 거절, 타 문서 정보 노출 없음 |
| F01-AC05 | 포트 사용 중 | MCP 활성화 | 시작 실패와 조치 안내, 성공 표시 없음 |
| F01-AC06 | 선택 문서·capability·유효기간 입력 | 연결 생성 | 권한과 token을 함께 저장, 잘못된 문서면 연결을 남기지 않음 |
| F01-AC07 | 활성/만료 token과 기존 작업 이력 | token 교체 | ID·권한·기록 유지, 구 token 거절·새 token 허용, 원문은 교체 직후만 표시 |
| F01-AC08 | token 만료 시각 도달 | 인증·문서/출력·기록 조회 | 접근 거절·민감한 결과 숨김, 기존 무기한 token은 그대로 동작 |
| F01-AC09 | 권한 초안 작성 중 | polling·탭 이동·서버 grant 변경 | 초안 유지, 충돌 시 최신 권한 재조회 전 저장 금지 |
| F01-AC10 | 연결 설정 완료 전/후 | 외부 클라이언트의 인증된 MCP 요청 | 실제 관측 시각으로 상태 갱신, 재시작/교체 후 미확인 상태 |

# 결정 기록

이 문서는 `00-reference-pdf` 작업이 진행되는 동안 확정되거나 변경된 결정을 시간순으로 기록한다. 아직 결정되지 않은 미래 기능은 기록하지 않는다.

## D-001 — Electron 사용

- 상태: 채택
- 이유: 참조 PDF와 결과 PDF를 동일한 Chromium 렌더링 엔진에서 생성하고 `printToPDF()`를 사용할 수 있다.

## D-002 — 로컬 전용 저장

- 상태: 채택
- 이유: 이력서 데이터는 서버, 계정과 네트워크 없이 사용자 컴퓨터에만 저장한다.

## D-003 — 참조 PDF 우선

- 상태: 채택
- 이유: 첫 작업의 성공 기준은 범용 편집기 기능의 수가 아니라 제공된 PDF의 시각적 재현과 PDF 내보내기다.

## D-004 — 다중 페이지 우선

- 상태: 채택
- 이유: 참조 PDF가 6페이지이므로 한 페이지 최적화나 초과 경고를 이번 작업에 포함하지 않는다.

## D-005 — 스타일 편집 UI 제외

- 상태: 채택
- 이유: 스타일 데이터 구조는 확장 가능하게 만들되 첫 구현에서는 `reference-resume-v1` 내장 스타일만 사용한다.

## D-006 — 단일 활성 문서

- 상태: 채택
- 이유: 데이터에 document ID와 저장소 경계를 두지만, 여러 이력서 버전을 생성·복제·삭제하는 UI는 이번 작업에 포함하지 않는다.

## D-007 — PDF 전용 출력

- 상태: 채택
- 이유: 시스템 프린터 인쇄는 제공하지 않고 PDF 파일 내보내기만 구현한다.

## D-008 — 작업 단위 문서는 시작할 때만 생성

- 상태: 채택
- 이유: 변경될 미래 기능과 설계를 미리 고정하지 않는다. `01`은 `00` 완료 후 실제 다음 목표가 정해질 때 생성한다.

## D-009 — 고정 스타일 에셋 하나만 제공

- 상태: 채택
- 이유: 첫 작업의 목표는 범용 스타일 편집기가 아니라 참조 PDF 수준의 결과물이다. 색상, 글꼴과 간격 선택 UI를 제공하지 않고 `reference-resume-v1` 스타일 에셋 하나만 사용한다.

## D-010 — 편집기와 PDF 스타일 분리

- 상태: 채택
- 이유: 앱 UI의 색상과 상태 표현이 최종 PDF에 영향을 주지 않도록 `AppStyle`과 `ResumeStyleSheet`를 분리한다.

## D-011 — 품질 기준은 참조 PDF 수준

- 상태: 채택
- 이유: 완전한 그래픽 편집 기능보다 타이포그래피, 그리드, 간격, 페이지 연결과 정보 계층이 참조 PDF와 동등한 수준으로 보이는 것을 우선한다.

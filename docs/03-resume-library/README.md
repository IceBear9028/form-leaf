# 03. 여러 이력서 보관함과 CRUD

## 상태

1차 구현 및 자동·실제 앱 검증 완료

## 문제

현재 앱은 실행 즉시 `default.resume.json` 한 개를 열기 때문에 목적이나 지원 회사별로 여러 이력서를 구분해 관리할 수 없다. 새 문서를 만들거나 다른 문서를 열고, 이름을 바꾸거나 삭제하는 진입점도 없다.

## 목표

- 앱 실행 시 이력서 목록을 먼저 표시한다.
- 여러 이력서를 만들고 서로 독립적으로 저장한다.
- 목록에서 원하는 이력서를 선택해 현재 편집 화면으로 들어간다.
- 편집 화면에서 저장을 보장한 뒤 목록으로 돌아간다.
- 목록에서 제목 변경과 삭제를 수행한다.
- 삭제한 이력서를 휴지통에서 확인하고 원래 목록으로 복원한다.
- 기존 단일 이력서를 최초 실행 때 안전하게 목록으로 이전한다.
- 기존 Markdown 편집, 자동 저장, PDF 내보내기와 데이터 스키마를 유지한다.

| 기능 | 포함 |
|---|---:|
| 이력서 목록과 빈 상태 | 예 |
| 새 이력서 생성 | 예 |
| 기존 이력서 열기 | 예 |
| 편집 후 자동 저장 | 예 |
| 목록 제목 변경 | 예 |
| 삭제 확인과 안전한 삭제 | 예 |
| 기존 단일 파일 자동 이전 | 예 |
| 최근 수정 순 자동 정렬 | 예 |
| 휴지통 목록과 개별 복원 | 예 |
| 휴지통 개별 영구 삭제 | 예 |
| 검색·태그·폴더·복제 | 아니요 |

## 기본 사용자 흐름

```text
앱 실행
  ↓
이력서 목록 ── 새 이력서 ──→ 빈 이력서 편집
  │                           │
  ├── 기존 이력서 클릭 ──────→ 기존 이력서 편집
  │                           │
  ├── 이름 변경               └── 저장 완료 후 목록으로
  ├── 삭제 확인 → 휴지통으로 이동
  └── 휴지통 → 이력서 복원 → 목록
```

## 이번 작업의 기본 결정

- 앱을 실행할 때마다 목록을 보여준다.
- 새 문서의 기본 제목은 `제목 없는 이력서`이며 같은 제목을 허용한다.
- 문서는 배열 위치가 아니라 기존 `documentId`로 식별한다.
- 목록은 `updatedAt` 기준 내림차순으로 자동 정렬하며, 사용자가 별도 정렬 방식을 선택하는 기능은 이번 범위에 넣지 않는다.
- 편집 화면 상단에 `이력서 목록` 버튼을 추가한다.
- 목록으로 이동하기 전에 대기 중인 자동 저장을 즉시 완료한다.
- 삭제는 확인 후 목록에서 제거하되 실제 파일은 앱 데이터의 `trash` 디렉터리로 옮긴다.
- 목록에서 휴지통 화면을 열 수 있고, 삭제한 이력서를 개별 복원할 수 있다.
- 휴지통에서 재확인 후 이력서와 백업을 완전히 삭제할 수 있다.
- 복원은 기존 `documentId`, 제목, 본문과 수정 시각을 유지한다.
- 기존 `default.resume.json`은 `내 이력서`라는 목록 항목으로 복사 이전하고 원본 파일을 보존한다.

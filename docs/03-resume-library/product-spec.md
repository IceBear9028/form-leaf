# 여러 이력서 보관함 제품 요구사항

## 화면 1: 이력서 목록

앱의 기본 시작 화면이다. 상단에는 제품명과 `새 이력서` 버튼을 두고, 본문에는 이력서 카드를 최근 수정 순으로 표시한다.

정렬 기준은 `updatedAt` 내림차순이다. 수정 시각이 같으면 `createdAt` 내림차순, 그래도 같으면 ID 오름차순으로 정렬해 앱을 다시 열어도 순서가 바뀌지 않게 한다. 사용자가 정렬 기준을 바꾸는 UI는 이번 MVP에 포함하지 않는다.

각 카드에는 다음 정보를 표시한다.

- 이력서 제목
- 프로필 이름. 값이 없으면 `프로필 이름 없음`
- 최근 수정 시각
- 카드 전체의 열기 동작
- 이름 변경 메뉴
- 삭제 메뉴

상단에는 `휴지통` 진입 버튼과 삭제된 이력서 수를 함께 표시한다.

카드 내부의 이름 변경·삭제 버튼은 카드 열기 동작과 분리한다. 키보드 사용자는 카드, 이름 변경, 삭제에 각각 접근할 수 있어야 한다.

### 빈 상태

이력서가 한 개도 없으면 오류 화면이 아니라 정상적인 빈 화면을 표시한다.

- 안내: `아직 작성한 이력서가 없습니다.`
- 기본 행동: `첫 이력서 만들기`
- 생성에 성공하면 새 문서 편집 화면으로 이동한다.

### 로딩과 오류

- 최초 목록 로딩 중에는 중복 생성이나 열기를 막는다.
- 목록 로드 실패 시 오류 내용과 `다시 시도`를 표시한다.
- 특정 문서 열기 실패는 전체 목록을 없애지 않고 해당 동작의 오류로 보여준다.

## 화면 2: 이력서 편집

기존 `EditorPanel + ResumePreview` 화면을 유지한다. 도구 막대 왼쪽에 `이력서 목록` 버튼과 현재 목록 제목을 표시한다.

- 문서 본문과 정형 필드 편집은 현재 동작을 그대로 사용한다.
- Preview Markdown 직접 편집, 실행 취소, 페이지네이션과 PDF 내보내기를 유지한다.
- `Cmd/Ctrl+S`는 현재 선택한 문서만 저장한다.
- 자동 저장 결과가 다른 문서에 적용되지 않도록 문서 ID를 저장 요청에 명시한다.
- 목록으로 돌아갈 때 변경 사항이 있으면 저장을 즉시 실행하고 성공한 뒤 이동한다.
- 저장 실패 시 편집 화면을 유지하고 오류 및 재시도를 제공한다.

## Create

1. 사용자가 목록에서 `새 이력서`를 누른다.
2. 앱은 새 `documentId`와 기본 `ResumeDocument`를 만든다.
3. 제목을 `제목 없는 이력서`로 설정한다.
4. 문서 파일과 목록 인덱스를 저장한다.
5. 생성된 문서의 편집 화면으로 이동한다.

생성 버튼은 요청 중 비활성화해 한 번의 클릭이 두 문서를 만들지 않게 한다.

## Read

- 목록에는 전체 본문을 싣지 않고 저장된 요약 정보만 반환한다.
- 카드를 누르면 ID로 문서 한 개를 로드한다.
- 존재하지 않거나 손상된 문서는 정상 문서로 대체하지 않는다.
- 손상 파일은 직전 `.backup` 복구를 시도하고, 실패하면 사용자에게 오류를 표시한다.

## Update

### 본문 저장

- 현재 650ms debounce 자동 저장을 유지한다.
- 저장할 문서의 `documentId`와 요청 ID가 일치하지 않으면 거부한다.
- 정상 저장 시 `updatedAt`을 갱신한다.
- 문서 저장 결과에서 갱신된 목록 요약을 반환해 목록 인덱스와 UI가 같은 값을 사용한다.

### 이름 변경

- 목록에서 이름 변경을 선택하면 현재 제목이 입력된 작은 dialog를 연다.
- 앞뒤 공백을 제거한 결과가 비어 있으면 `제목 없는 이력서`를 사용한다.
- 같은 제목은 허용하며 식별은 `documentId`로 한다.
- 제목 변경은 기존 `ResumeDocument.name`과 목록 요약을 한 작업으로 갱신한다.
- 편집 화면의 기존 `문서 이름` 필드를 수정해도 다음 저장에서 목록 제목이 함께 갱신된다.

## Delete

1. 삭제 dialog에 대상 제목을 표시한다.
2. `취소`를 기본 안전 행동으로 제공한다.
3. 확인하면 문서와 백업을 `workspaces/trash`로 이동한다.
4. 이동이 성공한 뒤 활성 목록에서 항목을 제거하고 휴지통 목록에 추가한다.
5. 실패하면 목록 항목을 유지하고 오류를 표시한다.

파일을 즉시 영구 제거하지 않는 것은 로컬 데이터 손실을 줄이기 위한 저장 정책이다.

## 휴지통과 Restore

목록 화면의 `휴지통` 버튼으로 별도 휴지통 화면에 들어간다.

휴지통 항목에는 다음 정보를 표시한다.

- 삭제 당시 이력서 제목
- 프로필 이름
- 삭제 시각
- 삭제 전 마지막 수정 시각
- 복원 버튼
- 완전 삭제 버튼

휴지통은 최근 삭제한 순으로 표시한다. 항목이 없으면 `휴지통이 비어 있습니다.`라는 정상 빈 상태와 목록으로 돌아가기 버튼을 제공한다.

복원 동작은 다음과 같다.

1. 사용자가 대상의 `복원` 버튼을 누른다.
2. 앱은 휴지통 파일과 백업을 원래 `resumes` 위치로 이동한다.
3. 기존 `documentId`, 제목, 본문, `createdAt`, `updatedAt`을 유지한다.
4. 활성 목록 인덱스에 다시 추가하고 휴지통 목록에서는 제거한다.
5. 완료 알림에서 복원된 이력서를 바로 열 수 있게 한다.

같은 ID의 활성 문서가 이미 있으면 어느 파일도 덮어쓰지 않고 복원을 거부한다. 같은 제목은 ID가 다르면 허용한다. 복원 자체는 본문 수정이 아니므로 `updatedAt`을 변경하지 않으며, 복원된 항목은 전체 목록의 최근 수정 순 규칙에 따라 배치한다.

### 완전 삭제

1. 사용자가 휴지통 항목의 `완전 삭제`를 누른다.
2. 확인 dialog에 대상 제목과 복구할 수 없다는 경고를 표시한다.
3. 명시적으로 다시 확인하면 해당 문서와 저장된 백업을 제거한다.
4. 다른 활성 문서와 휴지통 문서는 변경하지 않는다.
5. 실패하면 항목을 휴지통에 유지하고 오류를 표시한다.

영구 삭제는 휴지통에서만 제공한다. 예고 없는 데이터 손실을 피하기 위해 30일 자동 삭제는 적용하지 않는다. 휴지통 전체 비우기는 이번 MVP에서 제외한다.

## 기존 데이터 이전

기존 경로는 다음과 같다.

```text
workspaces/default.resume.json
workspaces/default.resume.json.backup
```

최초 목록 로드 때 인덱스가 없으면 다음 순서로 이전한다.

1. 기존 파일이 있으면 v1/v2 검증과 기존 마이그레이션을 수행한다.
2. `documentId`를 유지한 채 새 문서 저장 위치에 복사한다.
3. 문서 이름이 `새 이력서`이거나 비어 있으면 복사본의 `name`과 목록 제목을 모두 `내 이력서`로 설정하고, 그 외에는 기존 이름을 유지한다.
4. 새 인덱스를 원자적으로 저장한다.
5. 기존 파일과 백업은 삭제하거나 이름을 바꾸지 않는다.

앱이 중간에 종료되어도 같은 `documentId`의 문서를 중복 등록하지 않아야 한다. 기존 파일이 없으면 정상적인 빈 목록으로 시작하며 기본 문서를 자동 생성하지 않는다.

## 완료 기준

- 앱 실행 시 목록이 먼저 표시된다.
- 여러 문서를 생성하고 각각 다른 내용을 저장할 수 있다.
- 목록에서 선택한 문서만 열리고 수정된다.
- 목록 이동과 앱 재실행 후 변경 내용이 유지된다.
- 목록과 편집 화면 양쪽의 제목 변경이 동기화된다.
- 확인한 문서만 삭제되고 나머지 파일은 바뀌지 않는다.
- 삭제한 문서가 휴지통에 최근 삭제 순으로 표시된다.
- 휴지통에서 복원하면 동일한 ID와 내용으로 목록에 돌아온다.
- 확인한 휴지통 항목과 백업만 완전히 삭제되고 다시 복원할 수 없다.
- 마지막 문서를 삭제하면 정상 빈 상태가 표시된다.
- 기존 단일 이력서의 ID와 내용이 보존된 채 한 번만 이전된다.
- 기존 Markdown Preview 편집과 PDF 내보내기에 회귀가 없다.

# 미리보기 Markdown 직접 편집 구현 계획

## 진행 상태

| 단계 | 작업 | 상태 | 완료 기준 |
|---|---|---|---|
| 1 | 기능 범위와 편집 경계 확정 | 완료 | Markdown 본문 한정, 단일 편집 그룹 선택 |
| 2 | 원문 offset 매핑 프로토타입 | 완료 | 렌더링 텍스트 선택을 source range로 변환 |
| 3 | 미리보기 기본 텍스트 편집 | 완료 | 입력·삭제·한글 조합이 `bodyMarkdown`에 반영 |
| 4 | 선택 서식 트랜잭션 | 완료 | 인라인 서식 적용·해제와 링크 편집 |
| 5 | 상태 동기화와 페이지네이션 | 완료 | 커서·선택 복원과 자동 저장 연동 |
| 6 | 접근성·인쇄·회귀 검증 | 완료 | 단축키, PDF 제외 처리와 자동 테스트 통과 |

자동 검증은 완료했으며 실제 한글 IME와 긴 본문에 대한 사용자 검증을 남겨 둔다.

## 1. 기능 경계 확정

- 직접 편집 대상은 `bodyMarkdown`을 가진 본문으로 제한한다.
- 프로필·기간·기관·프로젝트명·기술 스택 등 정형 필드는 왼쪽 폼에서 유지한다.
- 선택 서식은 하나의 Markdown 원문과 하나의 최상위 블록 안에서만 허용한다.
- 지원할 인라인 서식과 1차 제외 노드를 확정한다.
- 편집 모드 진입, 종료와 선택 도구 표시 조건을 와이어 수준으로 확인한다.

## 2. source range 매핑

- 각 Markdown 본문에 안정적인 `sourceId`를 부여한다.
- mdast `position.start.offset`과 `position.end.offset`을 렌더링 요소에 전달한다.
- 텍스트·강조·링크·밑줄 렌더링 구간에 원문 offset 정보를 연결한다.
- 브라우저 `Selection`의 anchor/focus를 `{ sourceId, start, end }`로 변환한다.
- 역방향 선택과 한글·이모지처럼 UTF-16 offset에 영향을 주는 문자열을 검증한다.
- `++밑줄++` 확장과 이스케이프 문자가 offset을 잃지 않도록 별도 tokenizer 경계를 정의한다.

## 3. 기본 텍스트 편집

- 미리보기 Markdown 블록에 편집 가능 상태와 포커스 표현을 추가한다.
- `beforeinput`, `input`, `compositionstart/update/end`를 기준으로 입력을 처리한다.
- 브라우저가 만든 HTML을 저장하지 않고 source range 치환 연산만 만든다.
- 문자 입력, 선택 삭제, Backspace/Delete와 줄바꿈을 Markdown 원문 변경으로 변환한다.
- 코드 블록·표·이미지 등 1차 제외 노드는 읽기 전용으로 유지한다.
- 왼쪽 입력과 동일한 문서 변경 함수로 업데이트한다.

## 4. 선택 서식

- 선택 범위가 지원 조건을 만족할 때만 floating toolbar를 표시한다.
- 굵게·기울임·밑줄·취소선·인라인 코드의 토글 연산을 구현한다.
- 기존 mark가 선택 일부에만 걸친 경우의 동작을 정의하고 테스트한다.
- 링크 적용 시 URL 입력 UI를 표시하고 안전한 프로토콜 검증을 재사용한다.
- 키보드 단축키가 브라우저 기본 동작보다 편집 트랜잭션을 우선하도록 한다.
- 적용 후 원문 offset 변화량을 이용해 선택 범위를 복원한다.

## 5. 동기화와 페이지네이션

- 모든 변경을 `{ sourceId, range, replacement }` 트랜잭션으로 통일한다.
- 짧은 입력 동안 불필요한 전체 페이지 재측정을 줄이는 정책을 검토한다.
- 재페이지네이션으로 DOM이 교체된 뒤 source range 기준으로 커서를 복원한다.
- 편집 중인 블록이 다른 페이지로 이동하면 해당 블록이 보이도록 스크롤을 보정한다.
- 왼쪽 입력에서 수정한 경우 미리보기 편집 상태가 오래된 원문을 덮어쓰지 않도록 버전을 검사한다.
- 기존 자동 저장 debounce와 `.backup` 흐름을 그대로 사용한다.

## 6. 검증

- source range 변환과 Markdown 문자열 연산을 DOM과 분리해 단위 테스트한다.
- 한글 조합, 이모지, 영문, 줄바꿈과 역방향 선택을 검사한다.
- 중첩 mark와 링크 경계에서 적용·해제를 검사한다.
- 프로젝트가 페이지를 이동하는 길이의 입력을 수동 검증한다.
- 편집 UI가 PDF와 인쇄 DOM에서 제거되는지 확인한다.
- 기존 `npm test`, 타입 검사, 빌드와 개인정보 검사를 실행한다.

## 권장 구현 순서

1. 읽기 전용 상태에서 드래그 선택 → source range 표시 개발 도구
2. source range에 굵게 적용하는 순수 문자열 연산
3. 선택 toolbar와 굵게 토글 연결
4. 나머지 인라인 서식과 링크 연결
5. 기존 한 블록의 일반 텍스트 입력 연결
6. 줄바꿈·삭제·IME 처리 확장
7. 페이지네이션·선택 복원과 전체 회귀 검증

선택 서식의 source range 경계를 먼저 증명한 뒤 일반 입력을 연결한다. 렌더링 DOM 전체를 Markdown으로 재직렬화하는 구현은 사용하지 않는다.

# 02. 미리보기 Markdown 직접 편집

## 상태

1차 구현 완료 · 사용자 검증 대기

## 문제

현재 사용자는 왼쪽 편집기에서 Markdown 원문을 수정하고 오른쪽 미리보기에서 결과를 확인한다. 문장을 확인하다가 고치려면 다시 왼쪽에서 같은 항목을 찾아야 하므로 작성 위치와 결과 확인 위치가 분리되어 있다.

또한 미리보기에서 강조하고 싶은 문장을 발견해도 텍스트를 선택한 상태에서 바로 굵게, 기울임, 밑줄 같은 Markdown 서식을 적용할 수 없다.

## 기능 목표

- 오른쪽 미리보기의 Markdown 본문을 직접 수정할 수 있다.
- 미리보기에서 텍스트를 드래그하면 선택 영역 가까이에 서식 도구를 표시한다.
- 서식 변경은 렌더링된 DOM이 아니라 원본 `bodyMarkdown`을 수정한다.
- 왼쪽 Markdown 입력, 오른쪽 직접 편집과 저장 데이터는 항상 같은 원문을 공유한다.
- 편집 결과가 페이지네이션과 PDF 미리보기에 즉시 반영된다.

## 1차 범위

직접 편집과 선택 서식의 대상은 Markdown 본문으로 제한한다.

| 대상 | 미리보기 직접 편집 | 선택 서식 |
|---|---:|---:|
| 소개글 본문 | 지원 | 지원 |
| 경력 항목 본문 | 지원 | 지원 |
| 교육 항목 본문 | 지원 | 지원 |
| 프로젝트·사이드 프로젝트 본문 | 지원 | 지원 |
| 대외활동 본문 | 지원 | 지원 |
| 프리텍스트 본문 | 지원 | 지원 |
| 프로필 정보 | 제외 | 제외 |
| 섹션 제목 | 제외 | 제외 |
| 회사·기관·프로젝트명 | 제외 | 제외 |
| 기간·링크·기술 스택 | 제외 | 제외 |

정형 필드는 데이터 의미와 검증 규칙이 있으므로 기존 왼쪽 폼에서 편집한다. 이후 별도 작업에서 정형 필드의 미리보기 인라인 편집을 검토할 수 있지만 이번 작업에 포함하지 않는다.

## 목표 사용자 경험

### 본문 수정

1. 사용자가 미리보기의 Markdown 문단을 클릭한다.
2. 해당 블록이 편집 상태로 전환되고 커서가 클릭한 위치에 놓인다.
3. 사용자가 글자를 입력하거나 삭제한다.
4. 원본 `bodyMarkdown`이 갱신되고 왼쪽 입력과 페이지네이션이 함께 갱신된다.
5. 포커스가 빠져도 별도의 확인 버튼 없이 기존 자동 저장 흐름을 사용한다.

### 선택 서식

1. 사용자가 하나의 Markdown 본문 안에서 텍스트를 드래그한다.
2. 선택 영역 가까이에 작은 서식 도구가 표시된다.
3. 사용자가 굵게, 기울임, 밑줄, 취소선, 인라인 코드 또는 링크를 선택한다.
4. 선택한 원문 범위에 대응하는 Markdown 문법이 추가되거나 제거된다.
5. 선택 범위와 포커스를 가능한 한 유지한 채 미리보기를 다시 렌더링한다.

## 선택 서식 도구

1차 도구는 인라인 Markdown 서식만 제공한다.

| 기능 | Markdown | 동작 |
|---|---|---|
| 굵게 | `**내용**` | 선택 전체가 굵으면 제거, 아니면 적용 |
| 기울임 | `*내용*` | 선택 전체가 기울임이면 제거, 아니면 적용 |
| 밑줄 | `++내용++` | Resume Studio 확장 문법 적용·제거 |
| 취소선 | `~~내용~~` | GFM 취소선 적용·제거 |
| 인라인 코드 | `` `내용` `` | 선택 범위를 인라인 코드로 전환 |
| 링크 | `[내용](URL)` | URL 입력 후 링크 적용, 기존 링크는 수정·제거 |

H1~H6, 문단, 목록과 인용문은 블록 전체의 의미를 변경하는 기능이므로 드래그 선택용 인라인 도구와 분리한다. 1차 구현에서는 왼쪽 Markdown 입력으로 변경하고, 실제 사용성 검증 후 블록 도구 추가 여부를 결정한다.

## 편집 경계

- 선택은 같은 `bodyMarkdown` 안에서만 유효하다.
- 1차 구현은 하나의 최상위 Markdown 블록 안에 있는 선택만 서식 변경을 허용한다.
- 서로 다른 항목, 페이지 또는 Markdown 블록을 가로지르는 선택에는 도구를 표시하지 않는다.
- 이미지, 코드 블록, 표와 원문 HTML 영역은 1차 직접 편집에서 제외한다.
- 체크리스트 체크 상태 변경과 목록 구조 편집은 별도 동작으로 다룬다.
- PDF 출력과 인쇄 모드에서는 편집 UI와 선택 도구를 표시하지 않는다.

## 포함 범위

- 렌더링된 Markdown과 원문 offset의 양방향 매핑
- 미리보기 Markdown 문단·제목·목록 항목의 텍스트 수정
- 한글 IME 조합 입력과 일반 키보드 입력
- 선택 범위 기반 인라인 Markdown 적용·해제
- 링크 URL 입력·수정·제거
- 편집 후 선택·커서와 스크롤 위치 복원
- 기존 자동 저장, 백업과 페이지네이션 연동
- 키보드 단축키 `Cmd/Ctrl+B`, `Cmd/Ctrl+I`, `Cmd/Ctrl+U`
- source range 기반 편집 트랜잭션
- 연속 입력 단위의 `Cmd/Ctrl+Z`, `Cmd/Ctrl+Shift+Z` 실행 취소·다시 실행

## 제외 범위

- 정형 필드의 미리보기 직접 편집
- 블록 드래그 앤 드롭과 블록 순서 변경
- 여러 Markdown 블록을 가로지르는 서식 적용
- 실시간 공동 편집과 댓글
- 사용자 정의 색상·폰트·글자 크기
- 임의 HTML 편집
- 완전한 범용 WYSIWYG Markdown 편집기
- PDF 화면에서의 편집

## 완료 조건

- [x] 미리보기에서 지원 대상 Markdown 텍스트를 직접 수정할 수 있다.
- [x] 수정 결과가 해당 `bodyMarkdown`의 정확한 위치에 반영된다.
- [x] 왼쪽 입력과 오른쪽 미리보기가 같은 원문을 즉시 표시한다.
- [x] 드래그 선택 시 같은 편집 그룹 안에서만 서식 도구가 나타난다.
- [x] 굵게·기울임·밑줄·취소선·인라인 코드·링크를 적용하고 제거할 수 있다.
- [x] 한글 조합 중 문서 갱신을 유예하고 조합 종료 시 반영한다.
- [x] 재페이지네이션 뒤 source range를 기준으로 선택과 커서를 복원한다.
- [x] Enter 한 번으로 새 Markdown 블록을 만들고 해당 블록에서 바로 입력할 수 있다.
- [x] Shift+Enter로 현재 제목·문단·목록 블록 안에서만 줄바꿈할 수 있다.
- [x] 문장 끝에서도 연속 Space를 입력하고 바로 다음 글자를 쓰거나 Backspace로 공백을 지울 수 있다.
- [x] 연속 입력을 한 단위로 실행 취소·다시 실행할 수 있다.
- [x] 인쇄·PDF에서 편집 outline과 서식 도구를 숨긴다.
- [x] Markdown 파싱·마이그레이션·스타일 테스트와 프로덕션 빌드가 통과한다.
- [ ] 실제 사용자 입력으로 한글 IME, 긴 본문의 페이지 이동과 중첩 서식을 최종 검증한다.

## 구현 메모

- 하나의 Markdown 블록을 하나의 편집 host로 사용하며 인라인 서식 조각을 별도 입력칸으로 만들지 않는다.
- 일반 입력은 `beforeinput` source transaction으로 처리하고 붙여넣기는 plain text만 사용한다.
- `<br>` 강제 줄바꿈과 AST에 나타나지 않는 빈 블록을 source에 연결해 Shift+Enter와 연속 Enter 중 포커스를 유지한다.
- parser가 생략하는 문장 끝 공백을 source-mapped 구간으로 렌더링하고, 서식 경계의 공백은 닫는 marker 바깥에 삽입한다.
- 문서 변경 직후에는 현재 Markdown unit을 보이는 page slot에 먼저 반영하고, 비동기 재페이지네이션 완료 후 같은 source range로 다시 동기화한다.
- 문단·굵게·링크의 DOM 자식 경계를 inline marker 안쪽/바깥쪽 source offset으로 구분한다.
- soft break 변환 뒤에도 text와 break 노드의 source position을 보존한다.
- Backspace·Delete는 UTF-16 한 칸이 아니라 화면 grapheme 단위로 삭제한다.
- 표, 코드 블록, 인라인 코드, 이미지, 원문 HTML과 각주는 읽기 전용이다.
- 서식 도구는 같은 문단·제목·목록 항목 안에서 source range를 계산할 수 있을 때만 표시한다.
- 링크 입력은 1차 버전에서 작은 브라우저 dialog를 사용한다.
- 목록 항목을 자동 생성·들여쓰기하는 구조 편집은 후속 개선 범위다.

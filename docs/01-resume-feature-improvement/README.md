# 01. 이력서 편집 기능 및 데이터 구조 단순화

## 상태

검증 진행 중 — Markdown 기반 v2 구현과 실제 데이터 마이그레이션 완료, PDF 회귀 검증 대기

## 문제

현재 본문 편집기는 `문단`, `목록`, `성과 상세`, `링크 목록`, `기술 스택`을 각각 별도 블록으로 추가하고 관리한다. 특히 `성과 상세`는 `성과 제목`, `문제·배경`, `해결 과정`, `결과` 입력을 나누어 보여주기 때문에 사용자가 정해진 서술 공식을 따라야 하는 것처럼 느껴진다.

본문을 작성할 때마다 블록 종류를 선택하고, 블록별 이동·삭제와 내부 항목을 관리해야 하므로 글 작성보다 편집기 구조를 다루는 일이 많다.

## 확정한 기능 목표

카테고리별 정형 필드는 유지하고, 모든 서술형 본문을 하나의 Markdown 편집 영역으로 통합한다.

- 이름, 회사·기관, 직무·과정명, 기간, 소속, 링크, 기술 스택과 표시 여부는 카테고리 필드로 유지한다.
- 소개, 프로젝트 소개, 일반 문단, 목록과 성과 서술은 하나의 Markdown 본문에서 작성한다.
- 사용자가 `문제·배경 → 해결 과정 → 결과` 구조를 따르도록 요구하지 않는다.
- 본문 블록 추가·이동·삭제와 성과 전용 입력 UI를 제거한다.
- Markdown 결과는 오른쪽 이력서 미리보기에 현재 이력서 스타일로 즉시 반영한다.

## 목표 사용자 경험

사용자는 카테고리 항목을 열고 다음 두 종류의 정보만 편집한다.

1. 카테고리에 필요한 정형 필드
2. 하나의 Markdown 본문

예시:

```md
프로젝트에 대한 간단한 소개입니다.

### 검색 성능 개선

검색 조건이 많아질수록 응답 시간이 길어지는 문제가 있었습니다.

- 검색 조건과 요청 구조를 단순화했습니다.
- 반복 요청에 캐시를 적용했습니다.
- 평균 응답 시간을 40% 단축했습니다.
```

사용자는 단순한 문장 하나만 작성할 수도 있고, 필요하면 소제목과 목록을 자유롭게 조합할 수 있다. 서술 방식은 데이터 모델이나 UI가 강제하지 않는다.

## 카테고리별 편집 기능

| 카테고리 | 유지하는 정형 필드 | Markdown 본문 |
|---|---|---|
| 프로필 | 이름, 직무명, 사진, 전화번호, 이메일, 링크 | 사용하지 않음 |
| 소개글 | 섹션 제목 | 사용 |
| 경력 | 회사명, 직무, 기간, 링크 | 사용 |
| 교육 | 기관, 과정·학위, 기간, 링크 | 선택 사용 |
| 프로젝트 | 프로젝트명, 기간, 소속, 링크, 기술 스택 | 사용 |
| 사이드 프로젝트 | 프로젝트명, 기간, 소속, 링크, 기술 스택 | 사용 |
| 대외활동 | 활동명, 기간, 기관·주최, 링크 | 사용 |
| 프리텍스트 | 섹션 제목 | 사용 |

정형 필드는 작성 중인 빈 값도 자동 저장할 수 있다. 여기서 필드 유지 여부는 저장 유효성보다 편집 화면에서의 역할을 의미한다.

## Markdown 기능 범위

CommonMark 기본 문법과 GFM 확장 문법을 지원한다.

- H1~H6, 문단과 줄바꿈
- 문단 사이에 추가로 입력한 연속 빈 줄 보존
- 순서 없는 목록, 순서 목록, 중첩 목록과 체크리스트
- 굵게, 기울임, 취소선, 밑줄과 링크
- 인용문, 인라인 코드, 코드 블록과 구분선
- 이미지, 표, 자동 링크와 각주

파서는 `unified + remark-parse + remark-gfm + remark-breaks`를 사용한다. 밑줄은 표준 Markdown 문법에 없으므로 기존 데이터를 보존하는 `++내용++` 확장으로 제공한다. 임의 HTML은 실행하지 않고 텍스트로 표시한다.

## 제거하는 편집 기능

- `문단 추가`, `목록 추가`, `성과 상세 추가` 등 본문 블록 선택 UI
- `성과 제목`, `문제·배경`, `해결 과정`, `결과` 전용 입력 UI
- 본문 블록별 이동·삭제 버튼
- 프로젝트 소개와 본문을 나누어 작성하는 중복 입력 흐름

항목 자체의 추가·삭제·순서 변경·표시 여부는 계속 제공한다.

## 포함 범위

- 카테고리별 기존 정형 필드 유지
- 카테고리 항목별 단일 Markdown 본문 편집기
- CommonMark·GFM 문법의 미리보기 렌더링
- 문법 의미와 분리된 다중 이력서 스타일 기반
- `schemaVersion: 1` 본문을 Markdown 기반 새 버전으로 이전
- 기존 문장, 강조, 밑줄과 링크 보존
- 기존 `reference-resume-v1` 미리보기와 PDF 출력 회귀 검증
- 기존 로컬 JSON과 백업 파일 보호

## 제외 범위

- 이력서 문장 자동 작성·요약·교정
- 색상·글꼴·간격을 변경하는 스타일 편집기
- 새로운 PDF 디자인 템플릿
- 새로운 사용자 정의 카테고리
- 드래그 앤 드롭과 항목 복제
- 클라우드 저장과 계정 기능

- [x] 기존 본문 블록 선택 UI와 성과 전용 입력 UI가 제거된다.
- [x] 카테고리별 정형 필드와 항목 제어 기능은 유지된다.
- [x] CommonMark·GFM 기본 문법과 밑줄 확장이 미리보기와 PDF 렌더러에 연결된다.
- [x] 현재 참조 스타일을 유지하면서 같은 Markdown에 다른 이력서 스타일을 추가할 수 있다.

## 스타일 템플릿 범위

- Markdown 원문과 스타일은 `styleSheetId`로 분리한다.
- 등록된 프리셋은 본문 글꼴·색상·H1~H6·목록·코드·인용문·표와 프로젝트 제목 계층을 교체할 수 있다.
- `reference-resume-v1`과 `reference-resume-compact-v1` 두 프리셋으로 같은 Markdown의 스타일 교체를 검증한다.
- 현재 프리셋은 코드에 등록하고 다시 빌드해야 하며 사용자 정의 스타일 파일이나 스타일 편집 UI는 제공하지 않는다.
- 프로필·섹션 제목·그리드·세로선·페이지 여백 등 전체 이력서 레이아웃에는 아직 CSS 고정값이 남아 있다.

# 이력서 본문 Markdown 규칙

## 목적

이 문서는 이력서 본문에서 지원하는 Markdown 문법, 파싱 경계와 스타일 계약을 정의한다. Markdown 원문에는 내용의 의미만 저장하고 글꼴·크기·간격·목록 모양은 선택한 이력서 스타일이 결정한다.

## 파서와 렌더러

파싱 파이프라인은 다음 구성을 사용한다.

```text
Markdown 원문
→ unified + remark-parse
→ remark-gfm + remark-breaks
→ mdast
→ Resume Markdown React Renderer
→ 선택된 Resume Style
→ A4 미리보기 / PDF
```

- `remark-parse`가 CommonMark 문법을 mdast로 변환한다.
- `remark-gfm`이 표, 취소선, 체크리스트, 자동 링크와 각주를 추가한다.
- `remark-breaks`가 한 번의 줄바꿈을 강제 줄바꿈 노드로 변환한다.
- 표준 Markdown이 합치는 연속 빈 줄은 원문 위치 정보를 이용해 추가 줄 간격으로 보존한다.
- React 렌더러는 mdast를 직접 컴포넌트로 변환하며 HTML 문자열을 삽입하지 않는다.
- `++내용++`은 기존 밑줄 데이터를 보존하기 위한 Resume Studio 전용 확장이다.

## 지원 문법

### 블록 문법

| 기능 | 문법 예시 | mdast 의미 |
|---|---|---|
| 제목 | `# H1`부터 `###### H6` | `heading`, `depth: 1..6` |
| 문단 | 빈 줄로 구분 | `paragraph` |
| 줄바꿈 | 한 번의 줄바꿈 | `break` |
| 연속 빈 줄 | 문단 사이에 빈 줄 추가 | 기본 문단 구분 이후의 빈 줄마다 한 줄 높이 추가 |
| 순서 없는 목록 | `- 항목` | `list`, `ordered: false` |
| 순서 목록 | `1. 항목` | `list`, `ordered: true` |
| 중첩 목록 | 목록 아래 들여쓰기 | 중첩 `list` |
| 체크리스트 | `- [x] 완료` | `listItem.checked` |
| 인용문 | `> 내용` | `blockquote` |
| 코드 블록 | 세 개의 백틱 | `code` |
| 구분선 | `---` | `thematicBreak` |
| 표 | GFM 파이프 표 | `table` |
| 각주 | `[^1]`과 `[^1]: 내용` | `footnoteReference`, `footnoteDefinition` |

### 인라인 문법

| 기능 | 문법 예시 | 렌더링 |
|---|---|---|
| 굵게 | `**내용**` | `strong` |
| 기울임 | `*내용*` | `emphasis` |
| 취소선 | `~~내용~~` | `delete` |
| 밑줄 | `++내용++` | 전용 밑줄 표현 |
| 링크 | `[이름](https://example.com)` | 안전한 URL이면 링크 |
| 참조 링크 | `[이름][문서]` | 대응하는 definition 링크 |
| 이미지 | `![설명](https://...)` | 안전한 이미지 URL이면 이미지 |
| 인라인 코드 | `` `내용` `` | 인라인 코드 |
| 자동 링크 | `https://example.com` | GFM 링크 |
| 이스케이프 | `\` 다음 특수문자 | 원문 문자 |

밑줄 확장은 하나의 텍스트 노드 안에서 해석한다. 굵게나 링크 내부의 `++내용++`은 지원하지만, 밑줄 바깥에서 다른 Markdown 노드를 가로지르는 조합은 작성 규칙으로 보장하지 않는다.

## HTML 처리

임의 HTML은 실행하지 않는다. remark가 `html` 노드로 인식하더라도 React 렌더러는 해당 값을 텍스트로 출력한다. `dangerouslySetInnerHTML`은 사용하지 않는다.

링크는 `https:`, `http:`, `mailto:`만 활성화한다. 이미지는 `https:`, `http:`와 허용한 `data:image/*;base64` 형식만 표시한다. 허용하지 않는 링크와 이미지 주소는 실행하지 않고 텍스트 또는 대체 문구를 유지한다.

## 스타일 계약

모든 이력서 스타일은 다음 요소를 정의해야 한다.

- H1~H6의 글꼴 크기, 굵기, 행간과 앞뒤 간격
- 문단과 강제 줄바꿈
- 굵게, 기울임, 취소선, 밑줄, 링크와 인라인 코드
- 순서 없는 목록, 순서 목록, 중첩 목록과 체크리스트
- 인용문, 코드 블록, 구분선과 이미지
- 표의 헤더, 셀, 테두리와 정렬
- 각주와 원문 HTML 텍스트 표시
- 페이지 분할 시 블록 내부 분리 정책

공통 React 렌더러는 문법 의미만 컴포넌트로 변환한다. `resumeStyleSheets.ts`의 각 프리셋이 `MarkdownStyleTokens`를 제공하고 런타임이 이를 CSS custom property로 변환한다. 현재 `reference-resume-v1`과 `reference-resume-compact-v1`이 같은 렌더러에 서로 다른 크기·행간·간격을 제공한다. 이후 스타일도 파서나 저장 데이터를 바꾸지 않고 같은 계약을 구현한다.

기본 Markdown 표현은 VS Code Markdown Preview의 밝은 화면 규칙을 기준으로 한다.

- 본문 글꼴은 이력서의 기존 한글 인상을 유지하도록 `Pretendard`를 우선 사용한다.
- 일반 본문·목록·H1~H6의 기본 글자색은 인쇄 선명도를 위해 `#000000`을 사용한다.
- H1과 H2도 이력서 섹션 구분선과 겹치지 않도록 별도 하단선을 사용하지 않는다.
- H3~H6에는 별도 아이콘이나 도형을 붙이지 않는다.
- 순서 없는 목록은 문맥과 무관하게 표준 `disc` 마커를 사용한다.
- 중첩된 순서 없는 목록은 `circle`, `square` 순으로 구분한다.
- 링크는 파란색으로 표시하고 hover 상태에서 밑줄을 표시한다.
- 표는 전체 셀 테두리보다 헤더와 행 구분선을 중심으로 표시한다.

카테고리 문맥에 따라 화살표나 사각형 같은 별도 목록 마커를 사용하지 않는다. 스타일 프리셋은 글자 크기와 간격을 조정할 수 있지만 Markdown 요소의 일반적인 의미와 위계는 유지한다.

프로젝트와 사이드 프로젝트에서는 항목 제목이 본문 제목보다 상위에 보이도록 별도 크기 계층을 사용한다. 참조 스타일은 프로젝트 제목을 13pt로 표시하고 본문 H1~H6을 각각 12pt, 10.5pt, 9pt, 8pt, 7pt, 6.8pt로 제한한다. 소개글과 프리텍스트는 일반 Markdown H1~H6 크기를 유지한다. 프로젝트 제목과 프로젝트 문맥의 제목 크기는 모두 스타일 프리셋 토큰으로 정의한다.

프로젝트 Markdown의 첫 문단은 기존 `summary`가 차지하던 위치와 간격을 유지한다. 본문이 제목이나 목록부터 시작하면 빈 소개 영역을 만들지 않는다.

## 페이지네이션

- mdast의 최상위 노드를 기본 측정 단위로 사용한다.
- 제목, 문단, 목록, 인용문, 코드 블록, 표와 구분선은 각각 독립적인 최상위 블록이다.
- definition과 footnote definition은 본문 위치에서 보이지 않는다.
- 각주는 본문 끝의 각주 영역으로 렌더링한다.
- 향후 제목과 다음 블록 함께 배치, 목록 항목 내부 분리 방지 등의 정책을 mdast 노드 타입 기준으로 적용한다.

## v1→v2 변환 원칙

마이그레이션은 기존 문장을 새로 쓰거나 요약하지 않고 기존 순서를 유지해 Markdown 원문으로 직렬화한다.

- 소개글의 `paragraphs`는 빈 줄로 구분한 문단으로 합친다.
- 프로젝트 `summary`는 본문의 첫 문단으로 옮긴다.
- `paragraph`는 Markdown 문단으로 옮긴다.
- `bullet-list`는 `- ` 목록으로 옮긴다.
- `detail.title`은 `### ` 제목으로 옮긴다.
- `detail.context`는 제목 다음 문단으로 옮긴다.
- `detail.actions`와 `detail.result`는 기존 순서를 유지한 목록으로 옮긴다.
- 굵게, 밑줄과 링크 mark는 대응하는 Markdown 표기로 옮긴다.
- 원문의 Markdown 특수문자는 의도하지 않은 문법으로 바뀌지 않게 escape한다.
- `link-list`는 Markdown 링크 목록으로 변환한다.
- 프로젝트의 `tech-stack`은 정형 필드로 옮기고 그 밖의 위치에서는 `**기술 스택:** 값` 문단으로 보존한다.

## 작성 예시

```md
프로젝트의 목적과 역할을 간단히 설명합니다.

### 검색 성능 개선

요청 조건이 많아질수록 응답 시간이 길어지는 문제가 있었습니다.

- 검색 조건과 요청 구조를 단순화했습니다.
- 반복 요청에 캐시를 적용했습니다.
- 평균 응답 시간을 **40% 단축**했습니다.

자세한 내용은 [프로젝트 문서](https://example.com)에서 확인할 수 있습니다.
```

## 검증 항목

- CommonMark와 GFM 블록이 대응하는 mdast 노드로 파싱되는지 검사한다.
- 한 번의 줄바꿈이 `break` 노드로 변환되는지 검사한다.
- v1 직렬화 후 텍스트와 기존 mark가 보존되는지 검사한다.
- 원문 HTML이 실행되지 않고 텍스트로 표시되는지 검사한다.
- 허용하지 않은 URL이 활성 링크나 이미지로 만들어지지 않는지 검사한다.
- 각 이력서 스타일이 지원 문법 전체의 스타일을 정의하는지 시각적으로 검사한다.

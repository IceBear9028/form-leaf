## 구현 순서

### 1. 현재 구조 분석

- `ResumeSection`, `TimelineItem`, `ProjectItem`, `ContentBlock`의 중복과 차이를 기록한다.
- 본문 작성에 필요한 블록 선택·이동·삭제와 성과 전용 UI를 식별한다.
- 카테고리 정형 필드와 서술형 본문의 경계를 확인한다.

### 2. 기능 목표와 편집 UX 확정

- 카테고리별 정형 필드는 유지한다.
- 소개와 각 항목의 서술형 내용은 Markdown 본문 하나로 편집한다.
- 본문 블록 추가·정렬·삭제 UI와 성과 전용 필드를 제거한다.
- 항목 추가·삭제·순서 변경·숨김은 유지한다.
- 오른쪽 전체 이력서 미리보기를 Markdown 결과 확인 영역으로 사용한다.

### 3. Markdown 범위와 변환 규칙 확정

- CommonMark·GFM과 밑줄 확장의 표기 규칙을 확정한다.
- `unified + remark-parse + remark-gfm + remark-breaks`로 mdast를 생성한다.
- H1~H6, 문단, 목록, 인용문, 코드, 표, 이미지와 각주의 스타일 계약을 정의한다.
- Markdown 특수문자를 포함한 기존 문장을 변경 없이 옮기는 escaping 규칙을 정한다.
- 프로젝트 `summary`와 기존 콘텐츠 블록을 하나의 Markdown 본문으로 합치는 순서를 정한다.
- 기존 `DetailBlock`을 제목·문단·목록으로 옮기는 예시를 검토한다.
- 본문 안의 기존 링크 목록과 기술 스택 블록의 처리 규칙을 확정한다.
- 저장 데이터와 분리된 `#markdown-prototype` 화면에서 현재 이력서 스타일을 확인한다.
- Markdown 결과를 mdast 최상위 블록으로 나누어 이후 페이지네이션 단위로 사용할 수 있게 한다.

### 4. v2 타입과 마이그레이션

- v1 타입과 검증기를 마이그레이션 입력 경계에 유지한다.
- 카테고리 정형 필드와 Markdown 원문을 저장하는 v2 타입·검증기를 추가한다.
- 원본을 변경하지 않는 순수 v1→v2 변환 함수를 구현한다.
- 실제 사용자 데이터 대신 모든 블록과 mark 조합을 포함한 합성 fixture로 자동 검증한다.
- 최초 v2 저장 전에 덮어쓰지 않는 v1 전용 백업을 만든다.

### 5. 편집 UI 단순화

- `BlocksEditor`와 `BlockFields` 기반의 본문 블록 UI를 제거한다.
- 소개글과 프리텍스트의 여러 문단 카드도 Markdown 입력 하나로 교체한다.
- 경력·교육·프로젝트·사이드 프로젝트·대외활동의 각 항목에 Markdown 본문 입력 하나를 제공한다.
- 프로젝트 소개를 별도 입력하지 않고 Markdown 본문에 포함한다.
- 카테고리 정형 필드와 항목 제어 기능은 그대로 유지한다.

### 6. 미리보기 연결

- Markdown 원문을 안전한 이력서 콘텐츠로 변환한다.
- 지원 Markdown 전체를 공통 React 렌더러와 `reference-resume-v1` 스타일에 연결한다.
- 후속 이력서 스타일이 같은 문법 계약을 재정의할 수 있도록 파서·렌더러·스타일을 분리한다.
- 굵게, 밑줄과 링크가 기존 출력 능력을 유지하도록 한다.
- 프로젝트 제목과 첫 본문, 페이지네이션과 세로 구분선 관계를 회귀 검증한다.

### 7. 전체 검증

- 카테고리별 정형 필드와 Markdown 본문 생성·수정·삭제를 확인한다.
- 항목 추가·삭제·순서 변경·숨김을 확인한다.
- 실제 v1 문서를 v2로 변환하고 전용 `.v1.backup`을 검증한다. (완료)
- 앱 종료 후 재실행해 v2 문서 복원과 일반 `.backup` 생성을 확인한다. (완료)
- 손상된 현재 파일에서 일반 `.backup`으로 복구되는지 확인한다.
- 참조 PDF의 페이지 수, 텍스트, 링크와 주요 레이아웃을 비교한다.
